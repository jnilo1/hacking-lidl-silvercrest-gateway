# CLAUDE.md - Kernel & rtl8196e-eth driver development

## Goal

Replace the legacy `rtl819x` Ethernet driver with a new, clean `rtl8196e-eth` driver
for the Lidl Silvercrest Zigbee gateway (Realtek RTL8196E SoC, Lexra MIPS CPU).

The new driver targets: single physical port (port 4), zero-copy RX/TX, NAPI,
devicetree-based configuration, and >= 80 Mbps throughput on iperf.

The legacy driver works but is a direct port of Realtek's 2.6.30 SDK code -- it's
unmaintainable. The new driver is a clean-room rewrite for Linux 5.10.

## Directory layout

```
32-Kernel/
  files/                            # Platform overlay applied to every build
    arch/                           #   Realtek platform code (SoC, DTS, Lexra cache, ...)
    drivers/
      net/ethernet/
        rtl819x/                    #   Legacy SDK Ethernet driver
        rtl8196e-eth/               #   THE NEW DRIVER (source of truth, edit here)

  patches/                          # Patches against vanilla 5.10.246
                                    #   Lexra CPU, platform Kconfig/Makefile, skbuff.c hook
                                    #   (skbuff.c patch guarded with #ifdef CONFIG_RTL819X)

  config-5.10.246-realtek.txt       # Base kernel config (uses RTL819X=y)

  build_kernel.sh                   # Unified build script (both drivers, zboot)
  kbuild_dbg.sh                     # Incremental rebuild (needs a complete tree)
  flash_kernel.sh                   # Flash kernel.img via TFTP to gateway

  linux-5.10.246-rtl8196e-eth/      # BUILD TREE (generated by build_kernel.sh)
                                    #   DO NOT edit here -- edit files/ instead
```

## How the build works

`build_kernel.sh` creates the build tree by layering:

1. **Vanilla Linux 5.10.246** (downloaded)
2. **patches/** applied (Lexra CPU, platform Kconfig/Makefile, skbuff.c hook)
3. **files/** copied (platform code + both Ethernet drivers)
4. **.config** generated from `config-5.10.246-realtek.txt`:
   - new driver:    `RTL819X=n`, `RTL8196E_ETH=y` + `olddefconfig`
   - legacy driver: `RTL8196E_ETH=n`, `RTL819X=y` + `olddefconfig`
5. Compile + package via zboot -> output image

On re-run with an existing build tree, the kernel is rebuilt incrementally (no
re-extraction, no re-patching, no re-copy of files/).

## Development workflow

```bash
# Edit the driver source (always in files/, never in the build tree):
$EDITOR files/drivers/net/ethernet/rtl8196e-eth/rtl8196e_main.c

# Build with new driver (default):
./build_kernel.sh                   # → kernel-rtl8196e-eth.img

# Build with legacy driver (reference):
./build_kernel.sh legacy            # → kernel.img

# Clean rebuild from scratch:
./build_kernel.sh clean

# Flash to gateway (must be in bootloader mode at 192.168.1.6):
tftp -m binary 192.168.1.6 -c put kernel-rtl8196e-eth.img
```

**Important**: `build_kernel.sh` does NOT re-sync `files/` on incremental builds
(the build tree already has the driver). To pick up edits in `files/` without
a full clean, copy the changed file(s) manually into the build tree or run
`./build_kernel.sh clean`.

## The new driver: rtl8196e-eth

Source: `files/drivers/net/ethernet/rtl8196e-eth/`

### Architecture

| File | Role |
|------|------|
| `rtl8196e_main.c` | net_device, NAPI, IRQ, TX/RX scheduling, module params |
| `rtl8196e_hw.c/h` | MMIO register access, init sequence, KSEG1 helpers, PHY, L2 toCPU |
| `rtl8196e_ring.c/h` | TX/RX descriptor rings, napi_alloc_skb RX buffers, ownership, cache flush/invalidate |
| `rtl8196e_dt.c/h` | Devicetree parsing (interface@0 properties) |
| `rtl8196e_regs.h` | Register definitions (trimmed to what's needed) |
| `rtl8196e_desc.h` | Descriptor structures (pktHdr, mbuf) |

### Hardware constraints (RTL8196E-specific)

- DMA uses **KSEG1 addresses** (0xAxxxxxxx), not standard dma_addr_t.
- Must flush cache on TX (`dma_cache_wback_inv()`), invalidate on RX descriptor reads.
- Two RX rings required: pkthdr (descriptors) + mbuf (buffers).
- Init sequence: MEMCR, full reset, PHY init, ring setup, CPUICR, CPUIIMR, TRXRDY.
- L2 toCPU entry required for CPU packet reception.
- IRQ via SoC interrupt controller (GIMR bit 15).
- BIST must be skipped (don't block init).

### RX buffer management (napi_alloc_skb)

The RX hot path uses `napi_alloc_skb()` for buffer allocation. This API uses a
per-CPU page frag cache dedicated to NAPI context, avoiding locks and maximizing
cache locality. It internally adds `NET_SKB_PAD` headroom and calls `skb_reserve`.

Ring init uses `netdev_alloc_skb()` (no NAPI context available at probe time).

- Pre-allocated SKBs stored in shadow array `rx_bufs[]` (one `struct sk_buff *`
  per RX descriptor).
- On RX: the old SKB is handed to the stack via `napi_gro_receive()`, a new SKB
  is allocated with `napi_alloc_skb(napi, buf_size)`, and its `data` pointer is
  installed in the hardware descriptor.
- On destroy: `dev_kfree_skb_any()` for each `rx_bufs[i].skb`.
- No `page_pool`, no `build_skb()`, no PAGE_POOL Kconfig dependency.
- The `patches/net-core-skbuff.c.patch` is guarded with `#ifdef CONFIG_RTL819X`;
  it has no effect when `rtl8196e-eth` is selected.

### Devicetree bindings

The driver reads from the existing `&ethernet` node in `rtl8196e.dts`:

```dts
&ethernet {
    status = "okay";
    link-poll-ms = <1000>;

    interface@0 {
        reg = <0>;
        ifname = "eth0";
        local-mac-address = [02 14 B8 EE B7 54];
        vlan-id = <1>;
        member-ports = <0x10>;    /* port 4 */
        untag-ports = <0x10>;
        mtu = <1500>;
        phy-id = <4>;
    };
};
```

Only `interface@0` is used. Extra interface nodes are ignored with a warning.

### TX path design

The TX path is optimized for the uniprocessor Lexra SoC:

- **No spinlock**: `start_xmit` runs with BH disabled on this UP system, so
  softirq (NAPI, timers) cannot preempt. The ISR doesn't touch TX state.
- **No TX timer**: NAPI poll handles TX reclaim + queue wake via TX_DONE IRQs.
  Emergency reclaim in `start_xmit` handles ring-full edge cases.
- **No BQL**: Byte Queue Limits add atomic ops overhead unnecessary on a
  single-queue 100 Mbps embedded SoC.
- **`napi_consume_skb`**: TX reclaim uses batched SKB freeing when called
  from NAPI context (budget > 0), falling back to `dev_kfree_skb_any`
  equivalent when budget == 0.
- **Cache flush split**: packet data is flushed before `tx_submit`, only
  descriptor flushes (pkthdr + mbuf) happen inside the submit function.
- **TXFD kick on every packet**: hardware requires a pulse on every submit
  (conditional kick breaks boot — tested and confirmed).

### Performance

- iperf TCP RX: **~91 Mbps** (legacy: 85.3 Mbps, **+6%**)
- iperf TCP TX: **~44 Mbps** (legacy: 42.1 Mbps, **+5%**)
- No warnings in dmesg
- Stable SSH, ping IPv4/IPv6

Baseline measured in identical conditions (same host, same day, 10s iperf).
The new driver exceeds legacy on both RX and TX.

## Kernel config differences (vs legacy)

The new driver config differs from `config-5.10.246-realtek.txt` in these lines:
```
# CONFIG_RTL819X is not set    (was: CONFIG_RTL819X=y)
CONFIG_RTL8196E_ETH=y          (added)
```

All other RTL819X configs (serial, SPI, GPIO, clocksource, interrupt controller)
remain enabled -- they are platform infrastructure, not the Ethernet driver.

## Cross-compilation details

- **Toolchain**: `mips-lexra-linux-musl-gcc` 8.5.0 (crosstool-NG, in `x-tools/`)
- **ARCH**: mips (big-endian, 32-bit)
- **CPU**: Lexra RLX4181 (400 MHz, MIPS-1 + MIPS16 ISA, no ll/sc, 16 KB I-cache, 8 KB D-cache)
- **LOCALVERSION**: `-rtl8196e-eth`
- **Image format**: vmlinux → zboot (arch/mips/boot/compressed/) → objcopy → cvimg

## Testing procedure

The gateway has two network addresses depending on its state:
- **192.168.1.6** — bootloader (TFTP server for flashing)
- **192.168.1.126** — Linux (SSH, iperf)

### Build, flash, and test cycle

```bash
# 1. Build
./build_kernel.sh

# 2. Flash (gateway must be in bootloader mode at 192.168.1.6)
tftp -m binary 192.168.1.6 -c put kernel-rtl8196e-eth.img

# 3. Wait for boot (~20s), then verify
ssh root@192.168.1.126 dmesg | grep rtl8196e

# 4. Run iperf test (TCP RX + TX, 10s each)
./test_rtl8196e_eth.sh "description of what changed"

# The test script automatically puts the gateway back in boot mode
# (boothold) at the end, ready for the next flash cycle.
```

### test_rtl8196e_eth.sh

Runs two TCP iperf tests (~40s total including setup):
1. **TCP RX** (Ubuntu host → gateway): `iperf -c 192.168.1.126 -t 10`
2. **TCP TX** (gateway → Ubuntu host): `iperf -c <host_ip> -t 10` from gateway

Reports: throughput, interface stats (errors/drops), TCP retransmissions,
and comparison vs legacy rtl819x baseline.

Results are saved in `test_results_YYYYMMDD_HHMMSS/`.

### Baseline comparison

Measured in identical conditions (same host, same day, 10s iperf):

| Test | rtl819x (legacy) | rtl8196e-eth v1.0 |
|------|-------------------|-------------------|
| TCP RX (host → gw) | 85.3 Mbps | ~91 Mbps (**+6%**) |
| TCP TX (gw → host) | 42.1 Mbps | ~44 Mbps (**+5%**) |

## Reference: the legacy driver (rtl819x)

Located in `files/drivers/net/ethernet/rtl819x/`. This is the working driver
ported from Realtek's 2.6.30 SDK. It's complex (AsicDriver, l2Driver, vlan,
netif, swNic layers) but functional. Use `build_kernel.sh legacy` to build a
kernel with it when you need a known-working reference.

### Size comparison (pure LOC, excluding comments and blank lines)

| Driver | Files | Pure LOC |
|--------|-------|----------|
| `rtl8196e-eth` (new) | 9 | **1 842** |
| `rtl819x` (legacy) | 17 | **9 664** |

**5.2× reduction** in code size for equivalent (and better) functionality on this
hardware. The legacy driver carries unused layers (FDB, event manager, full L2/VLAN
tables) inherited from the 2.6.30 SDK.

## Important rules

- **Do NOT add "Co-Authored-By" lines to git commit messages.**
- **Never edit files in the build tree** (`linux-5.10.246-rtl8196e-eth/`).
  Always edit `files/drivers/net/ethernet/rtl8196e-eth/` (source of truth).
  After editing, run `./build_kernel.sh clean` for a clean build, or copy the
  changed file into the build tree for a quick incremental rebuild.
- The two drivers (`rtl819x` and `rtl8196e-eth`) conflict on the same hardware.
  Only one can be enabled at a time in `.config` (Kconfig enforces this).
- `flash_kernel.sh` expects `kernel.img`. The new build produces
  `kernel-rtl8196e-eth.img`. Copy or symlink as needed.
